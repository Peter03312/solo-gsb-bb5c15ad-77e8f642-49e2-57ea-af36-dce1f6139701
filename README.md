# 排练字幕修订 Web 应用

本地运行的排练字幕（SRT）修订工具。导入 SRT 原稿后，可在**两条独立的修订分支**上修正文案与起止时间、拆分/合并片段；合并时按**来源片段**做三方比对，双方同时改动的片段会并列展示并由人工选择，未冲突改动自动保留。导出前强制时间线校验，并可随时查看/恢复原稿。

在修订分支或合并分支上还可执行**可复核的放映质检（QC）**：为每份稿件配置质检规则（单条显示时长上下限、每秒可见字符数上限、相邻片段最小间隔、禁用词），按当前文字与时码生成报告、逐条列出命中与原稿来源；可对具体命中填写**有严格时效的豁免**，全部命中处理完且时间线无误后才能通过质检专用下载导出 SRT。

视频重剪后，可在任一修订分支或合并分支上对一段**连续的原稿来源序号区间**做**可预览的时码重排**：区间内片段保持相对位置等比重排，区间之后整体平移，区间之前不动；先预览每条受影响片段的新旧时码与时间线问题，确认后才整体提交。

排练时还可**按演员核对台词**：为稿件登记演员姓名，在修订分支或合并分支上为每个字幕片段指定一名演员；拆分沿用原演员，合并仅在演员相同时沿用、否则清空并提示重新指定，改文案不改归属、重剪重排只动时码。三方合并把演员归属纳入来源区间比较（单侧改动继承该侧，双方在同一区间指定不同演员按冲突逐处选侧，不按保存先后覆盖）。可按当前分支导出**演员走词单**：逐条给出演员、时码、台词与原稿来源序号；有未归属片段或时间线错误时列出具体片段并拒绝整份导出。

为方便海外演员排练，每个分支片段还可录入**双语译文并逐条复核**：译文与原文绑定，原文改动后译文保留作参考但转为待复核，纯时码调整不影响复核状态；拆分两条均保留原译文待复核，合并按原顺序拼接译文待复核，恢复原稿/整支重置清空受影响译文。三方合并把译文与复核状态一并纳入来源区间比较，双方译文或状态不同时按冲突逐处选侧。全部片段译文齐备且已复核、时间线无误后，可导出**双语 SRT**（逐段原文+译文，沿用当前时码与连续编号）；任何空译文、待复核片段或时间线错误都会列出具体片段并拒绝整份导出。

排练交付时，可从任一**修订分支或合并分支**签发不可变的**交付包（ZIP）**：包内同时包含按签发时同一次一致状态生成的**普通 SRT、双语 SRT、演员走词单与清单**，清单记录稿件与分支、签发时间、质检规则版本（含规则指纹）以及各文件 SHA-256，整包 ZIP 与清单自身的 SHA-256 记录在签发记录中。签发须同时满足四类闸门：**普通时间线无误、双语译文全部齐备且已复核、片段全部归属演员、放映质检实时核验通过**（与质检专用下载同口径：当前规则、已生成报告、未豁免命中为 0、时间线无误；报告失效仅提示）；任一项失败都按类别列出片段或规则问题，**整包不留存**。全部读取、核验与固化在单个同步事务内完成，签发期间发生改稿、改演员或改质检设置都不可能混入不同版本。已签发包可列出、查看清单并随时重下整包或单文件，**后续任何修改不改变已签发包内容**；删除稿件时自动清理所属交付包。

## 功能

- **导入 SRT**：严格校验序号连续、时间码格式、起点早于终点、片段不重叠；发现错误时列出具体行号与原因并**拒绝整份稿件**（不写入任何数据）。
- **双修订分支**：每份原稿导入时自动建立「修订分支 A / B」，各自独立编辑，互不影响。
- **片段编辑**：修改文案、起止时间；按时间码拆分片段；与下一片段合并；单片段恢复原稿；整条分支重置。
- **三方合并**：
  - 只被一方改动的来源区间 → 自动保留该方改动；
  - 双方都触及同一来源区间（含拆分/合并边界不同）→ 标记为冲突，并列展示 A/B 各自完整内容，必须逐处选择采用哪一方，**不以保存先后覆盖**；
  - 双方都未动 → 保留原稿；
  - 合并结果保存为新分支（含来源关联，可再次合并/导出/质检）。
- **放映质检（QC）**：
  - **规则配置（按稿件）**：单条显示时长下限/上限（秒）、每秒可见字符数上限（字符/秒）、相邻片段最小间隔（秒）、禁用词；空白不计字符，中文字符与标点各算一字；阈值留空表示该项不启用。无效阈值（≤0、非数字、下限大于上限）、空词、重复词一律**拒绝保存**。
  - **规则版本化**：规则内容实质变化时归档为新版本；豁免只对创建时的规则版本有效，规则变化后须用新版本重新生成报告。
  - **质检报告**：在修订分支或合并分支上按当前文字与时码生成，逐条列出命中规则、片段序号、原稿来源序号、时间码与具体原因，同时列出时间线问题；报告是生成时刻的快照，**编辑、拆分或合并后旧报告立即标记失效，不得沿用旧结果**，须重新生成。
  - **逐条豁免**：可对某条命中填写豁免理由；豁免仅对该分支当时的片段内容、时码与规则版本有效——片段文案/时码再变（含拆分、合并、恢复原稿）、片段消失或规则版本变化，豁免自动失效并在新报告中列明失效原因；也可手动撤销豁免。
  - **质检专用下载**：导出时**重新实时核验**当前分支片段、当前规则、当前豁免与时间线；仍有未豁免命中、时间线错误或报告已失效时**不生成 SRT** 并返回具体问题清单；全部通过后导出序号从 1 连续编号的 SRT。
- **导出校验（原有）**：检查时间非负、起点早于终点、片段不重叠；失败时列出问题片段序号与原因，**不生成文件**；通过后导出序号从 1 连续编号的 SRT。
- **重剪重排（本轮新增）**：在任一修订/合并分支上选择连续原稿来源序号区间 `[lo, hi]` 并填写该区间在新版视频中的起止时码：
  - **区间之前**的片段时码完全不动；
  - **区间内完整片段**按原有相对位置等比重排（线性映射 `新位置 = 新起点 + (原位置 − 原起点) × (新区间时长 ÷ 原区间时长)`，同一拆分切点只舍入一次，不会错开）；
  - **区间之后**的片段按「新区间终点 − 原区间终点」整体平移；
  - **结构约束**：同一来源拆出的片段必须一起处理（同在内或同在外）；跨越选择边界的合并片段（来源集合横跨 `lo`/`hi`）一律拒绝；区间内每个来源序号都必须能在分支上找到对应片段；
  - **两段式确认**：先调用预览接口/点「生成预览」，逐条展示受影响片段的新旧时码、角色（区间内/区间后）、是否实际变化，以及换算问题（负时码、等比重算后零时长）与时间线问题；预览返回一次性令牌。预览后分支被编辑、拆分、合并或重置，提交返回 409 并要求重新预览；
  - **原子提交**：确认在单事务内完成，整体成功或不改动；无效区间、新区间非正时长、负时码、片段重叠、换算后片段时长为零均给出原因并拒绝；
  - 只有**换算后时码确实变化**的片段才推进修订计数，使对应旧质检豁免/旧报告失效；时码未变的片段不会被误判为改动，既有豁免继续有效；质检导出仍按当前状态实时核验。
- **原稿管理**：在线查看原始 SRT、一键下载原稿、删除稿件。
- **演员登记与归属（本轮新增）**：
  - 为每份稿件维护演员名单（增/改名/删除，同稿件内姓名唯一；删除演员会把其在该稿件各分支上的归属清空）；
  - 在修订分支或合并分支的片段表格「演员」列逐条指定一名演员（可随时改派或清除）；页面同时显示**未归属片段**与**各演员的台词顺序**；
  - **拆分**：两条均沿用原演员；**与下条合并**：仅当两条演员相同（含都为空）时沿用，否则清空归属并提示重新指定；
  - **修改文案/起止时间不改变归属**；**重剪重排只更新时码**，归属原样保留（归属变化也不推进片段修订计数，不影响质检报告/豁免）；单条/整条恢复原稿时归属尽量按来源保留，来源曾被拆给不同演员等歧义情形清空。
- **演员走词单（本轮新增）**：
  - 按当前分支实时计算，按演员分组、组内按分支顺序给出每条台词的**演员、时码、台词文本与原稿来源序号**；
  - 存在**未归属片段**或**时间线错误**时逐条列出具体片段（片段序号、时码、原因）并**拒绝整份导出**；全部满足后下载纯文本走词单（也提供 JSON 接口供二次处理）。
- **合并中的演员归属（本轮新增）**：三方合并把演员归属纳入来源区间比较——
  - 仅一侧在某来源区间指定/改动演员（或同时改文案）→ 自动继承该侧；
  - 双方在同一区间都有改动但内容与演员**完全一致** → 自动保留，不报冲突；
  - 双方在同一来源区间指定**不同演员**（或一边有归属一边为空，且文案/结构也有差异）→ 列为**冲突**，冲突卡片显示各自演员，必须逐处手动选 A/B，**不按保存先后覆盖**；未逐处选择不能生成合并分支。
- **双语译文与复核（本轮新增）**：
  - 每个分支片段可录入一条译文并**标记已复核**；**空译文不能复核**；译文内容一旦修改即自动回到待复核；
  - 译文与对应原文绑定：**原文改动后译文保留供参考但转为待复核**；**纯时码调整（含重剪重排）不影响复核状态**；
  - **拆分**：两条均保留原译文作参考且转为待复核；**与下条合并**：按原顺序拼接两条已有译文（跳过空译文）且转为待复核；**恢复原稿 / 整支重置**：清空受影响译文；
  - 译文与复核状态的变化**不推进片段 rev**，不影响质检报告与豁免；但会使重剪重排的预览令牌过期（与演员归属一致）；
  - **三方合并**把译文与复核状态纳入来源区间比较：仅一侧改动自动继承该侧；双方改动完全一致（含译文与状态）自动保留；双方在同一区间都有改动且**译文或复核状态不同**时列为冲突，预览中并列展示各自译文与状态，逐处选侧后**所选内容与状态一并进入合并分支**；
  - **双语 SRT 导出**：逐段输出原文与译文，沿用当前时码，序号从 1 连续编号；**任何空译文、待复核片段或时间线错误都列出具体片段并拒绝整份导出**（可先调检查接口/点「双语导出检查」查看阻断原因）。现有单语 SRT、质检与演员走词单行为不变。
- **排练交付包（本轮新增）**：
  - 在任一修订分支或合并分支上签发**不可变交付包 ZIP**，内含按签发时**同一次一致状态**生成的普通 SRT、双语 SRT、演员走词单与**清单**；清单记录稿件与分支、签发时间、片段数、一致状态指纹、质检规则版本号/指纹、报告时效状态及每个文件的包内路径、字节数与 SHA-256（清单文件与整包 ZIP 的 SHA-256 记录在签发记录/接口返回中）；
  - **签发闸门**（任一失败即按类别返回片段或规则问题，409 且整包不留存）：① 普通时间线无误；② 双语译文全部非空且已复核；③ 全部片段已归属演员；④ 放映质检实时核验——复用质检专用下载口径（当前规则、已生成报告、当前豁免有效、未豁免命中为 0；报告失效仅作提示，不单独阻断）；
  - **一致性**：读取快照、四类闸门核验、四个文件生成与整包固化全部在同一个同步数据库事务内完成，签发期间的改稿、改演员归属或改质检设置不可能混入不同版本；失败整体回滚，不写任何包/文件记录；
  - **不可变与生命周期**：整包 ZIP 与每个文件内容固化在库中，后续修改不改变已签发包，可列出、查看详情（含清单与全部哈希）、重下整包或包内单文件；删除稿件时所属包随外键级联清理。

## 技术栈

- 后端：Node.js 20 + Express
- 数据库：SQLite（better-sqlite3，同步事务，WAL 模式，外键级联）
- 前端：原生 HTML/CSS/JavaScript（无需构建）
- 部署：Docker / Docker Compose（多阶段镜像内含依赖安装与数据库自动初始化）

## 快速开始（Docker Compose，推荐）

需要 Docker 20.10+ 与 Docker Compose v2。

```bash
docker compose up -d --build
```

启动后访问：

- **http://localhost:3000**

停止：

```bash
docker compose down          # 保留数据
docker compose down -v       # 同时删除数据库卷
```

### 配置

通过环境变量配置（可写入项目根目录的 `.env` 文件）：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `APP_PORT` | `3000` | 宿主机映射端口（容器内固定监听 3000） |
| `PORT` | `3000` | 容器/进程监听端口（直接用 Node 运行时生效） |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DATA_DIR` | `./data` | SQLite 数据库目录（Compose 中为命名卷 `/app/data`） |
| `DB_PATH` | `$DATA_DIR/app.db` | 数据库文件完整路径 |

例如改用 8080 端口：

```bash
APP_PORT=8080 docker compose up -d --build
# 访问 http://localhost:8080
```

数据保存在 Docker 命名卷 `srt-data` 中，重建容器不会丢失。

## 直接用 Node.js 运行（不使用 Docker）

```bash
npm install
npm start
# 访问 http://localhost:3000
```

数据库文件在首次启动时自动创建于 `./data/app.db` 并完成全部建表初始化，无需手动导入 SQL。

## 使用说明

1. 点击右上角 **导入 SRT**，选择本地 `.srt` 文件；若格式有误，弹窗会逐条列出「第 N 行」的错误，修正后重新导入即可。
2. 在顶部标签切换 **修订分支 A / B**，直接在表格中编辑文案与时间码，逐行点 **保存**；
   - **拆分**：输入切点时间码，把一条切成两条，两条均继承原来源；
   - **与下条合并**：合并相邻两条，来源取并集，时间取外边界，之后可再调整文案；
   - **恢复原稿**：把单条还原为原稿内容；**整条重置为原稿** 会丢弃该分支全部修改。
3. 两条分支修订完成后，点击 **合并两条分支**：
   - 预览每组来源区间的处理方式（未改动 / 仅 A 改 / 仅 B 改 / 冲突）；
   - 冲突处点击左侧或右侧卡片选择采用 A 还是 B，全部选择后生成合并分支。
4. 在合并分支（或任意分支）上点 **导出前检查**；通过后点 **导出 SRT** 下载序号连续的文件；检查不通过时按提示修复，服务器同样会拒绝生成文件。
5. **放映质检（本轮新增）**：
   1. 点右上角 **质检规则**，按需填写单条显示时长上下限（秒）、每秒可见字符数上限、相邻片段最小间隔（秒）与禁用词（每行一个）；无效阈值、空词或重复词会被拒绝保存。规则实质修改会产生新版本。
   2. 切换到任意修订分支或合并分支，在页面底部 **放映质检** 面板点 **生成质检报告**：报告会按当前文字与时码列出每条命中的规则、片段序号、原稿来源、时间码与原因，以及时间线问题。
   3. 对可接受的命中点 **填写豁免理由**。豁免只对此分支当前片段内容、时码与规则版本有效；之后改文案、改时间、拆分、合并、恢复原稿或修改规则，豁免立即失效（新报告会列出失效原因），需要重新评估；也可随时 **撤销豁免**。
   4. 编辑/拆分/合并后旧报告会在面板顶部红色提示「不得沿用」，此时请 **重新生成质检报告** 再处理。
   5. 点 **质检专用下载**：服务器重新核验当前片段、规则、豁免与时间线；存在未豁免命中、时间线错误或报告失效时不生成 SRT，并逐条返回具体问题；全部通过后才下载连续编号的 SRT。
6. **重剪重排（本轮新增）**：切换到任意修订分支或合并分支，点工具栏 **重剪重排**：
   1. 填写连续的**来源起始/结束序号**与该区间在新版视频中的**新起点/新终点时码**（`HH:MM:SS,mmm`），点 **生成预览**；
   2. 预览中显示原区间→新区间、等比系数、区间后平移量，以及每条受影响片段（区间内等比、区间后平移）的新旧时码；区间前片段不在列表中（不动）；
   3. 若存在换算问题（换算后负时码、等比重算后零时长）或时间线问题（起点不早于终点、片段重叠等），问题逐条列出且 **确认提交** 禁用；跨界合并片段、无效区间会直接拒绝并给出原因；
   4. 核对无误后点 **确认提交**：服务器校验预览令牌——预览后该分支若被编辑、拆分、合并或重置，会返回「预览已过期」，请重新生成预览；提交整体成功或不改动。提交后时码实际变化的片段旧质检豁免/旧报告自动失效，未变化片段不受影响（请按第 5 步重新生成质检报告）。
7. **演员与走词单（本轮新增）**：
   1. 点右上角 **演员名单**，逐条添加演员姓名（也可重命名/删除；删除会清空该演员在各分支上的归属）。
   2. 在片段表格 **演员** 列为每个片段指定一名演员；未归属的行底色加亮并标注「未归属」。
      - **拆分**自动沿用原演员；**与下条合并**仅在两条演员相同时沿用，否则会提示「已清空演员归属，请重新指定」；
      - 改文案/时间、重剪重排都不会改变归属。
   3. 页面底部 **演员走词单** 面板实时显示未归属片段清单（若有）以及各演员按出场顺序的台词（时码、台词、原稿来源序号）。
   4. 点工具栏或面板上的 **下载演员走词单**：全部片段已归属且时间线无误才生成 `.txt`；存在未归属片段或时间线错误时逐条列出并拒绝整份导出。
8. **双语译文与导出（本轮新增）**：
   1. 在片段表格 **译文** 列为每个片段录入译文，点 **存译文** 保存；行内徽章显示「未翻译 / 待复核 / 已复核」。
   2. 核对译文无误后点 **标记已复核**（空译文不能复核，按钮禁用）；如需再改，保存新译文会自动回到待复核，也可随时点 **取消复核**。
   3. 注意生命周期：改**原文**后译文保留但转为待复核；只改时码（含重剪重排）不影响复核状态；**拆分**两条都带原译文且待复核；**与下条合并**译文按原顺序拼接且待复核；**恢复原稿 / 整条重置**会清空译文。
   4. 点 **双语导出检查** 查看阻断原因（哪些片段空译文/待复核、是否有时间线错误）；全部解决后点 **导出双语 SRT** 下载逐段「原文+译文」的文件；仍有问题时服务器会逐条列出并拒绝整份导出。
   5. 合并两条分支时，译文与复核状态随各来源区间一并比较：冲突卡片会显示双方译文与复核状态，逐处选侧后所选内容与状态一并进入合并分支。
9. **排练交付（本轮新增）**：
   1. 在任一修订分支或合并分支页面底部找到 **排练交付** 面板（工具栏也有「签发交付包」按钮）；面板列出当前分支已签发的包。
   2. 点 **签发交付包** 并确认：服务器在单个事务内按当前内容同时核验四道闸门——普通时间线、双语译文（非空且已复核）、演员归属（无未归属片段）、放映质检实时核验（当前规则、已有报告、未豁免命中为 0）。
   3. 任一闸门失败时弹窗与面板会**按类别**逐条列出问题片段或规则（时间线 / 双语 / 演员 / 质检，含已失效豁免与报告失效提示）；本次**整包不留存**，处理后重新签发即可。
   4. 全部通过后生成 ZIP 并自动下载：包内顶层目录为 `交付包<编号>/`，含普通 SRT、双语 SRT、演员走词单与 `清单-交付包<编号>.txt`（记录稿件/分支、签发时间、质检规则版本与各文件 SHA-256）。
   5. 已签发包**内容不可变**：之后改稿、改演员或改质检规则，面板中的旧包与各文件哈希均不变，可随时点 **下载整包 ZIP** 或单独重下四个文件；删除稿件会清理其全部交付包。
10. 顶部 **查看原稿 / 下载原稿** 可随时对照与恢复原始稿件。

## SRT 格式要求

```
1
00:00:01,000 --> 00:00:04,000
第一句台词

2
00:00:04,500 --> 00:00:07,200
第二句台词（可多行）
```

- 序号必须从 1 开始且连续；
- 时间码格式 `HH:MM:SS,mmm --> HH:MM:SS,mmm`；
- 每条至少一行非空正文；
- 起点严格早于终点，相邻片段时间不重叠。

## 数据模型（简述）

- `scripts`：稿件与原始 SRT 全文；
- `actors`：稿件级演员名单（`UNIQUE(script_id, name)`），删除时片段归属置空；
- `source_segments`：解析后的原稿片段（合并识别的基准）；
- `branches`：修订分支与合并结果分支；
- `branch_segments`：分支上的当前片段（`rev` 为片段修订计数，文案/时码任一变化即 +1，驱动豁免失效；`actor_id` 为演员归属，可空，**归属变化不推进 rev**；`translation`/`translation_reviewed` 为译文与复核状态，**译文变化也不推进 rev**）；
- `segment_sources`：分支片段 ↔ 来源片段多对多关联（拆分=一对多，合并=多对一）；
- `qc_rules` / `qc_rule_versions`：每稿件当前质检规则指针 + 历史版本归档；
- `qc_reports` / `qc_hits`：质检报告快照与其命中（规则、片段序号、原稿来源、原因），附生成时的分支状态指纹与时间线问题；
- `qc_exemptions`：逐条命中豁免，绑定分支、规则版本、片段 id 与 `rev`、命中指纹，片段或规则任一变化即失效；
- `delivery_packages` / `delivery_files`：排练交付包签发记录（不可变）。整包 ZIP（`zip_blob` 与 `zip_sha256`）及包内普通 SRT / 双语 SRT / 走词单 / 清单四个文件内容、大小与 SHA-256 均固化在库；另记录签发时间、片段数、一致状态指纹（片段快照 + 质检规则指纹）与签发时规则版本指针；两表均外键挂稿件/分支，删除稿件时级联清理。

合并算法以来源序号为轴遍历，依据双方在同一区间的区块（普通/拆分/合并）决定自动保留或提请冲突选择；区块「是否改动」同时比较文案/时码/结构、演员归属与译文/复核状态，双方区块完全一致（含演员、译文与复核状态）时自动保留（`both_same`），否则任一差异（含演员或译文/状态不同）都进入冲突，由用户逐处选侧，不以保存先后覆盖；所选侧的文案、演员归属、译文与复核状态一并写入合并分支。

重剪重排不新增数据表：预览令牌是「分支片段状态指纹（身份/顺序/时码/文案/来源/演员归属/译文/复核状态/rev）+ 重排参数」的哈希（无状态）；提交在单事务内批量更新时码，仅换算后时码实际变化的片段 `rev = rev + 1`，因此旧豁免/旧报告只对真正变动的片段失效，未变化片段不被误判；演员归属与译文复核状态不随时码变化而改变。

演员归属不新增关联表，直接作为 `branch_segments.actor_id` 随片段走：拆分复制、合并不一致则清空、文案编辑与重排均不触碰。走词单在读取时实时按归属与时码分组计算，导出前强制「无未归属片段 + 时间线无错误」闸门。

译文同样随片段走（`branch_segments.translation` / `translation_reviewed`）：原文改动→译文保留转待复核；纯时码调整→状态不变；拆分→两条复制且待复核；合并→按原顺序拼接且待复核；恢复原稿/整支重置→清空。双语导出闸门实时检查「每片段译文非空 + 已复核 + 时间线无错误」，任一不满足即列出片段并拒绝整份导出。

质检判定以当前片段实时计算为准：报告用于可复核留档与豁免操作，质检导出闸门不依赖旧报告，而是重新核验分支、规则、豁免与时间线。

交付签发不引入任何异步或临时文件：`delivery.js` 在单个 better-sqlite3 同步事务内完成「读取同一份分支片段快照 → 四类闸门（普通时间线 / 双语 / 演员 / 质检）全部用该快照实时核验 → 从该快照生成三份交付物与清单 → 计算各文件 SHA-256 并构建 ZIP（内置极简 STORE 打包器，UTF-8 文件名）→ 写入 `delivery_packages`/`delivery_files`」，任一闸门失败或写库异常整体回滚，不留存任何包内容。包文件以 BLOB 固化，重下即从库中读取，与当前分支状态彻底解耦，因此后续改稿/改演员/改规则都不影响已签发包。

### 重剪重排接口与调用示例

预览请求字段：

| 字段 | 说明 |
| --- | --- |
| `source_start` / `source_end` | 连续原稿来源序号区间（≥1 整数，start ≤ end） |
| `new_start` / `new_end` | 区间在新版视频中的起止时码：`HH:MM:SS,mmm` 字符串，或非负整数毫秒；终点必须严格晚于起点 |

预览响应（200）含：`old_range`/`new_range`（区间原/新时码）、`shift_ms`（区间后平移量 = 新终点−原终点）、`scale_ratio`（等比系数）、`counts`（before/inside/after/changed 数量）、`affected[]`（每条受影响片段的 `ord`、`source_seqs`、`role=inside|after`、`old_timecode`、`new_timecode`、`time_changed`）、`errors`（换算问题）、`timeline_issues`（时间线问题）、`can_apply` 与一次性 `token`。结构不合法（跨界合并、来源缺失、区间无效）时直接返回 400 与 `recut_errors`，不发令牌。

确认时把同样参数与预览所得 `token` 原样回传；预览后分支发生编辑/拆分/合并/重置会得到 409 `{"preview_stale":true}`，需重新预览。

```bash
# 1) 预览：把分支 1 上来源片段 #2–#3 重排到新版视频的 00:00:05,000 ~ 00:00:10,000
curl -s -X POST http://localhost:3000/api/branches/1/recut/preview \
  -H 'Content-Type: application/json' \
  -d '{"source_start":2,"source_end":3,"new_start":"00:00:05,000","new_end":"00:00:10,000"}'
# => can_apply:true 时记录 token，并核对 affected[].old_timecode / new_timecode

# 2) 确认提交（毫秒整数亦可；token 必须来自针对当前分支状态的同参数预览）
curl -s -X POST http://localhost:3000/api/branches/1/recut/apply \
  -H 'Content-Type: application/json' \
  -d '{"source_start":2,"source_end":3,"new_start":5000,"new_end":10000,"token":"<预览返回的 token>"}'
# => {"ok":true,"counts":{"changed":3,...}}；若返回 409 preview_stale，请重新预览
```

### 演员与走词单接口及调用示例

```bash
# 1) 为稿件登记演员（同稿件内姓名唯一）
curl -s -X POST http://localhost:3000/api/scripts/1/actors \
  -H 'Content-Type: application/json' -d '{"name":"张三"}'
# => {"ok":true,"actor":{"id":1,"name":"张三"}}
curl -s http://localhost:3000/api/scripts/1/actors
# => {"script_id":1,"actors":[{"id":1,"name":"张三","assigned_count":0,"created_at":"..."}]}

# 2) 在某分支上为片段指定演员（actor_id 传 null 即清除归属）；
#    只改归属：文案/时码不变、rev 不增加，质检报告与豁免不受影响
curl -s -X PUT http://localhost:3000/api/branches/1/segments/10/actor \
  -H 'Content-Type: application/json' -d '{"actor_id":1}'
# => {"ok":true,"changed":true,"actor_id":1}

# 3) 拆分沿用原演员；合并仅在演员相同时沿用，否则清空并提示重新指定
curl -s -X POST http://localhost:3000/api/branches/1/segments/10/split \
  -H 'Content-Type: application/json' -d '{"cut_ms":2000}'
# => {"ok":true,"actor_id":1,"actor_carried":true}
curl -s -X POST http://localhost:3000/api/branches/1/segments/10/merge-with-next \
  -H 'Content-Type: application/json' -d '{}'
# 演员不同 => {"ok":true,"actor_carried":false,"actor_id":null,
#              "notice":"相邻片段演员不同（或其一未归属），合并后已清空演员归属，请重新指定"}

# 4) 走词单 JSON：未归属片段 + 时间线问题 + 各演员台词顺序
curl -s http://localhost:3000/api/branches/1/cue-sheet
# => {"can_export":false,
#     "unassigned":[{"ord":2,"timecode":"00:00:03,600 --> 00:00:06,200",
#                    "text_excerpt":"灯光渐亮…","message":"片段 #2 尚未归属演员…"}],
#     "timeline_issues":[],
#     "cue_sheet":[{"actor_id":1,"actor_name":"张三","line_count":1,
#                   "lines":[{"ord":1,"timecode":"00:00:01,000 --> 00:00:03,500",
#                             "text":"…","source_seqs":[1],"start_ms":1000,"end_ms":3500}]}],
#     "total_lines":4}

# 5) 下载走词单：有未归属片段或时间线错误时返回 409 并逐条列出，不生成文件
curl -s -i http://localhost:3000/api/branches/1/cue-sheet/export
# HTTP/1.1 409 Conflict
# {"error":"演员走词单导出被拒绝（未归属片段 1 条，时间线问题 0 处）…",
#  "unassigned":[{"ord":2,...}],"timeline_issues":[]}
# 全部归属且时间线无误后 => HTTP 200，Content-Type: text/plain，
# 内容按演员分组，逐条给出 演员 / 时码 / 台词 / 原稿来源序号。
```

合并预览/提交也已纳入演员归属：`/api/merge/preview` 的每个条目片段都带 `actor_id`/`actor_name`；
单侧改动的条目（`a_only`/`b_only`）与双方一致条目（`both_same`）自动处理，双方在同一来源区间指定不同演员的条目为 `conflict`，
`/api/merge/apply` 仍要求在 `resolutions` 中对每个冲突逐处选 `"A"`/`"B"`，否则返回 400 `unresolved`。所选侧的演员归属随片段写入合并分支。

### 双语译文接口与调用示例

片段对象新增字段：`translation`（译文，`null`=未录入）、`translation_reviewed`（0 待复核 / 1 已复核）。

```bash
# 1) 录入译文（传空字符串清除；译文内容变化会自动回到待复核）
curl -s -X PUT http://localhost:3000/api/branches/1/segments/10/translation \
  -H 'Content-Type: application/json' -d '{"translation":"Act One opens, everyone in position"}'
# => {"ok":true,"changed":true,"translation":"Act One opens, everyone in position","translation_reviewed":0}

# 2) 标记已复核 / 取消复核（空译文复核返回 400）
curl -s -X PUT http://localhost:3000/api/branches/1/segments/10/translation/review \
  -H 'Content-Type: application/json' -d '{"reviewed":true}'
# => {"ok":true,"changed":true,"translation_reviewed":1}

# 3) 生命周期速查：
#    PATCH 改原文     => 译文保留，translation_reviewed 变 0（响应带 translation_stale:true）
#    PATCH 只改时码   => 复核状态不变（重剪重排同理）
#    split            => 两条都带原译文且待复核（响应带 translation_carried:true）
#    merge-with-next  => 译文按原顺序拼接且待复核（响应带 translation_carried/translation_pending）
#    reset / reset-all=> 清空受影响译文（响应带 translation_cleared / translations_cleared）

# 4) 双语导出检查：逐条列出空译文、待复核片段与时间线问题
curl -s http://localhost:3000/api/branches/1/bilingual/validate
# => {"ok":false,"segment_count":4,"translated":3,"reviewed":2,
#     "bilingual_issues":[{"ord":2,"timecode":"00:00:03,600 --> 00:00:06,200",
#                          "issue":"missing_translation","message":"片段 #2 缺少译文…"},
#                         {"ord":3,"issue":"pending_review","message":"片段 #3 译文尚未复核…",...}],
#     "timeline_issues":[]}

# 5) 导出双语 SRT：任何空译文/待复核/时间线错误都拒绝整份导出（409 并逐条列出）
curl -s -i http://localhost:3000/api/branches/1/export-bilingual
# HTTP/1.1 409 Conflict
# {"error":"双语字幕导出被拒绝（空译文/待复核 2 条，时间线问题 0 处）…",
#  "bilingual_issues":[...],"timeline_issues":[]}
# 全部片段译文齐备且已复核、时间线无误后 => HTTP 200，逐段输出原文与译文：
#   1
#   00:00:01,000 --> 00:00:03,500
#   第一幕开场，全体就位
#   Act One opens, everyone in position
```

三方合并同样比较译文与复核状态：`/api/merge/preview` 的片段带 `translation`/`translation_reviewed`，
双方在同一来源区间的译文或复核状态不同即为 `conflict`（完全一致则 `both_same` 自动保留），
`/api/merge/apply` 逐处选侧后，所选侧的译文与复核状态一并写入合并分支。

### 排练交付接口与调用示例

```bash
# 1) 签发（在修订分支或合并分支上均可）；成功返回 201 + 包详情
curl -s -X POST http://localhost:3000/api/branches/1/deliveries
# 失败示例（HTTP 409）：按类别给出闸门问题，本次不留存任何包
# {
#   "error": "交付包签发被拒绝（双语问题 2 条，未归属片段 1 条，质检未达标（…）…）…",
#   "delivery_issues": {
#     "timeline":  {"ok": true,  "label": "普通时间线", "issues": []},
#     "bilingual": {"ok": false, "label": "双语译文复核",
#                   "issues": [{"ord": 2, "issue": "missing_translation", ...}]},
#     "actors":    {"ok": false, "label": "演员归属",
#                   "issues": [{"ord": 3, "timecode": "...", "message": "片段 #3 尚未归属演员…"}]},
#     "qc":        {"ok": false, "label": "放映质检",
#                   "precondition": [{"code": "report_missing", "message": "尚未生成质检报告…"}],
#                   "unresolved_hits": [...], "invalid_exemptions": [...], "report_stale": false}
#   }
# }

# 2) 成功后：列出已签发包 / 查看详情（含各文件与整包 SHA-256）
curl -s http://localhost:3000/api/branches/1/deliveries
curl -s http://localhost:3000/api/deliveries/1 | head -40

# 3) 重下：整包 ZIP（交付包1/ 目录内含 4 个文件），或包内单个文件
curl -s -o pkg.zip http://localhost:3000/api/deliveries/1/download
curl -s -o cue.txt   http://localhost:3000/api/deliveries/1/files/cue_sheet
# role 取值：srt | bilingual_srt | cue_sheet | manifest
```

`files[]` 中每个文件含 `role`、`filename`、`size_bytes` 与 `sha256`；包顶层另有
`zip_filename` / `zip_size` / `zip_sha256`、`state_hash`（签发一致状态指纹）、
`rule_version_no` / `rule_fingerprint` 与 `issued_at`。包内 `manifest` 为人类可读清单，
`manifest` 字段（JSON）内容与之对应。已签发包不随稿件后续编辑变化；删除稿件即级联删除其全部包。
